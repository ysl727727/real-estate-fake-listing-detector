## 1. 개요

### 1.1 대상 업무

매물 광고 정보를 국토교통부고시 「부당한 중개대상물 표시·광고행위의 유형 및 기준」
(제2026-345호, 2026.7.3. 일부개정)에 대조하여 부당 표시·광고 해당 여부와 유형을
판정하는 어시스턴트를 가정한다.

| 항목 | 내용 |
|---|---|
| 사용자 | 부동산 플랫폼 매물 검수 담당자 |
| 입력 | 판정 기준 조항 발췌 + 점검 대상 광고 정보 |
| 출력 | 판정 / 유형 / 근거 3줄 |
| 자료 제공 방식 | 조항을 프롬프트에 직접 포함 (in-context QA, 검색·RAG 없음) |
| 한국어 성능 | 중요 (기준·광고·판정이 전부 한국어) |
| 데이터 통제 | 필요 (미검수 매물 정보 및 중개사 정보 포함) |
| 응답 속도 | 중요도 중간 (실시간 대화가 아닌 검수 배치 작업) |
| GPU 환경 | RTX 5060 Laptop, VRAM 8,151 MiB |

### 1.2 Use Case 선정 근거

- 공식 판정 기준이 존재하여 정답이 객관적으로 확정된다
- "방향 90도 이상 차이" 등 수치 기준이 있어 경계 사례를 설계할 수 있다
- 출력 형식을 강제할 수 있어 Instruction Following을 정량화할 수 있다
- 미검수 매물·중개사 정보를 다루므로 로컬 운영의 근거가 성립한다

## 2. 실험 설계

### 2.1 통제 조건

본 실험 시작 전에 확정하였으며 종료 시까지 변경하지 않았다.

| 항목 | 값 |
|---|---|
| system 프롬프트 | 10개 질문 전체, 모든 모델 동일 |
| temperature | 1 |
| seed | 42 |
| num_predict (출력 한도) | 1,024 |
| num_ctx (전체 한도) | 4,096 |
| 파라미터 규모 | 4B (로컬 두 모델 동일) |
| 양자화 수준 | Q4_K_M (로컬 두 모델 동일) |
| instruct 튜닝 | 두 모델 모두 instruct 버전 |
| 내부 추론 | 미사용 (로컬 non-thinking / Cloud reasoning_tokens 0 실측) |

### 2.2 조건 정렬을 위한 재실험

생성 설정 불일치와 재현성 확보를 위해 전체 실험을 3회 수행하였다.

| 회차 | 조건 | gemma3 | qwen3 | 격차 | 처리 |
|---|---|---|---|---|---|
| 1차 | temp 0 / seed 42 | 55.1% | 85.0% | 29.9%p | Cloud와 temperature 불일치로 제외 |
| 2차 | temp 1 / seed 미지정 | 50.1% | 75.6% | 25.5%p | 재현성 미확보로 제외 |
| **3차** | **temp 1 / seed 42** | **57.0%** | **80.8%** | **23.8%p** | **본 집계** |

3개 조건 모두에서 선정 결과가 동일하였다.
제외된 기록은 `results/archive_temp0/`, `results/archive_noseed/`에 보관하였다.

### 2.3 내부 추론 조건 확인

Cloud 비교 모델 `gpt-5.6-luna`는 추론 수준 조절이 가능한 계열이며, 로컬 후보는
non-thinking 전용이므로 조건 불일치 가능성을 검증하였다.

`usage.completion_tokens_details.reasoning_tokens`를 실측한 결과 단순 인사말과
실험 문항(Q06) 모두 0이었다. 본 실험에 사용한 Chat Completions 엔드포인트에서는
추론이 동작하지 않은 것으로 확인된다. (검증 스크립트: `check_reasoning.py`)

단, 정확한 서술은 "이 모델이 추론을 사용하지 않는다"가 아니라 "본 구성에서
사용되지 않았다"이다. 추론 수준 상향 시의 변화는 측정하지 않았다.

## 4. 평가 방법

### 4.1 평가 문항

고정 10개 문항을 사용하였다.

| ID | 유형 | 정답 |
|---|---|---|
| Q01 | 정상 | 해당 / 부존재·허위 / (다) |
| Q02 | 정상 | 해당 / 거짓·과장 / (다) 방향 90도 이상 |
| Q03 | 정상 | 해당 / 거짓·과장 / (라) 직선거리 |
| Q04 | 정상 | 해당 / 거짓·과장 / (다) 사진 도용 |
| Q05 | 정상 | 미해당 / 해당없음 |
| Q06 | 경계 | 미해당 (45도는 90도 미만) |
| Q07 | 경계 | 미해당 (기망 행위 미확인) |
| Q08 | 경계 | 판단불가 ('현저하게'의 수치 기준 부재) |
| Q09 | 범위밖 | 과태료 정보 없음 안내 |
| Q10 | 범위밖 | 법적 판단 범위 밖 안내 |

정답 분포는 해당 4 / 미해당 3 / 판단불가 1 / 범위밖 2로 분산되어 있어,
단일 답변 반복 시 상한은 4/10이다.

### 4.2 문항 예시 (Q06)

**제공 자료**

```
[판정 기준 발췌] 국토교통부고시 (제2026-345호, 2026.7.3. 일부개정)
중개대상물의 내용을 현저하게 과장한 광고(거짓·과장)의 유형과 기준
(가) 방향이 광고 시 제시한 방향과 90도 이상 차이가 나는 경우
(나) 주요 교통시설과의 거리를 실제 도보거리나 도보시간이 아니라
     직선거리로 표시·광고하는 경우

[점검 대상 광고]
· 광고 내용: F빌라 201호, 남향
· 확인된 사실: 실제 주된 채광 방향은 남동향(광고 표기와 45도 차이)
```

**요구 출력 형식**

```
판정: 해당 / 미해당 / 판단불가 중 하나
유형: 부존재·허위 / 거짓·과장 / 기만적 / 해당없음 중 하나
근거: 적용한 조항과 판단 이유를 2~3문장으로
```

**정답** — 판정: 미해당 / 유형: 해당없음 / 근거: 45도는 90도 기준 미달

상식적 판단으로는 위반에 해당할 것으로 보이나 기준 수치상으로는 미해당이다.
모델이 자체 판단이 아닌 제공 기준을 적용하는지 검증하는 문항이다.
동일 성격의 함정 문항으로 Q07을 추가 배치하였다.

### 4.3 채점 방식

- `questions.json`의 `expected` 체크리스트 항목당 1점
- 문항별 만점이 상이하므로 획득/만점 = 달성률(%)로 환산
- 문항별 달성률의 평균으로 10개 문항을 동일 가중 처리
- 점수 근거 응답 문장을 `scores.csv`의 `note` 열에 인용 기록
- 모델이 실제 출력한 판정값을 `verdict` 열에 기록
- 답변 내 판정이 복수 등장 시 첫 번째 `판정:` 줄을 공식 출력으로 채점

### 4.4 선정 기준

필수 통과 조건과 선호 우선순위의 2단계로 구성하였다.

**필수 통과 조건**

| 조건 | 확인 방법 | gemma3 | qwen3 |
|---|---|---|---|
| 8GB VRAM에서 GPU 실행 | `ollama ps`의 PROCESSOR | 충족 (100% GPU) | 충족 (100% GPU) |
| 상업적 사용 가능 License | 약관 원문 확인 | 조건부 충족 | 충족 |
| 4,096 context 동작 | `ollama ps`의 CONTEXT | 충족 | 충족 |
| 자료 밖 내용 미생성 | 범위밖 문항 Q09·Q10 | **미충족 (50.0%)** | 충족 (54.2%) |

**선호 우선순위**

| 순위 | 기준 |
|---|---|
| 1 | 자료 밖 내용을 생성하지 않는가 (환각 회피) |
| 2 | 답변 정확성 |
| 3 | 전체 응답 시간 |
| 4 | VRAM 사용량 |

가중치 총점 방식을 채택하지 않았다. 총점 방식에서는 속도·VRAM 항목으로
환각 결함이 상쇄될 수 있으므로 2단계로 분리하였다.

## 6. 선정 및 근거

### 6.1 선정 결과

필수 통과 조건 단계에서 gemma3가 "자료 밖 내용 미생성" 항목에 미달하여 탈락하였다.
선호 우선순위를 적용하여도 결과는 동일하다.

| 순위 | 기준 | gemma3 | qwen3 | 우위 |
|---|---|---|---|---|
| 1 | 자료 밖 내용 회피 | 50.0% | 54.2% | qwen3 |
| 2 | 답변 정확성 | 57.0% | 80.8% | qwen3 |
| 3 | 전체 응답 시간 | 1.48초 | 2.22초 | gemma3 |
| 4 | VRAM | 2,742 MiB | 3,031 MiB | gemma3 |

3·4순위는 gemma3가 우세하나, 실험 전 확정한 순서에 따라 1순위를 우선 적용하였다.

### 6.2 결정적 사유 (1) — 자료 역독

Q07은 계약 완료 매물이 게시 중인 사례로, 기준 (가)는 "기망 행위가 확인된 경우"를
요건으로 한다. 제공 자료에는 "다른 매물을 권유한 사실도 확인되지 않음"으로 명시되어
있다. gemma3의 응답은 다음과 같다.

> 통보받지 않았고, 문의도 없으며, 다른 매물을 권유한 사실도 **확인되었습니다.**
> 이는 (중략) 허위·미끼 매물로 활용한 기망 행위에 해당합니다.

부정을 긍정으로 역독하고 존재하지 않는 사실을 근거로 위반을 인정하였으며,
2개 회차 모두 동일하였다. qwen3는 기망 행위 불성립을 근거로 미해당 판정하였다.

해당 기준은 2026년 7월 개정 내용으로 두 모델의 학습 데이터에 포함되었을 가능성이
낮으므로, 이 차이는 사전 지식이 아니라 제공 자료의 조건절을 판정에 반영하는
능력의 차이로 해석된다.

### 6.3 결정적 사유 (2) — 형식 및 지시 미준수

| 사례 | 내용 |
|---|---|
| Q05 | 정상 광고임에도 판정 칸에 '판단불가' 기입. 2회차는 "판단이 불가능합니다" 직후 "해당하지 않음을 확인할 수 있습니다"로 자기모순 |
| Q10 | 판정 기준에 없는 "중개 의무 위반" 개념을 도입. 법적 판단 금지 지시를 명시했음에도 자의적 판단 수행 |
| 선행 실험 | 판정 칸에 유형 선택지 기입, 선택지 4개 전체 복사 출력 사례 발생 |

## 7. Local–Cloud 비교

### 7.1 공통 문항 결과

비교 문항 5개(Q01, Q03, Q05, Q06, Q10)는 결과 확인 이전에 선정하였으며,
정상 3 / 경계 1 / 범위밖 1로 원 비율을 유지하였다.

| 문항 | gemma3 | qwen3 | cloud-luna |
|---|---|---|---|
| Q01 | 60.0% | 100% | 100% |
| Q03 | 75.0% | 100% | 100% |
| Q05 | 60.0% | 100% | 100% |
| Q06 | 37.5% | 50.0% | 100% |
| Q10 | 50.0% | 33.3% | 100% |
| **평균** | 56.5% | 76.7% | **100%** |

반복 수는 로컬 각 2회(모델당 10회), Cloud 각 1회(5회)이다.
호출 성공은 gemma3 10/10, qwen3 10/10, cloud-luna 5/5이다.

Cloud만 통과한 문항은 2개이다.

| 문항 | 내용 |
|---|---|
| Q06 | Cloud는 45도 < 90도를 2문장 71토큰으로 정리 후 종료. qwen3는 928토큰을 사용하며 판정 블록을 4회 출력하고도 첫 판정 줄이 오답 |
| Q10 | Cloud는 판단불가 처리 후 손해배상·승소 가능성이 기준 범위 밖임을 명시. 로컬 2종은 승소 가능성을 언급하지 않음 |

### 7.2 항목별 비교

| 기준 | Local (qwen3) | Cloud (gpt-5.6-luna) | 구분 |
|---|---|---|---|
| Quality | 공통 5문항 76.7% (n=10) | 공통 5문항 100% (n=5) | 실측 |
| Latency | 평균 2.22초 (n=20) | 평균 2.73초 (n=5) | 실측 |
| Cost | 호출 요금 없음 (장비·전력·관리 비용 별도) | 5회 $0.001097 | 실측 |
| Security | 매물·중개사 정보 외부 미전송 | 외부 API 전송 | 분석 |
| Infrastructure | RTX 5060 8GB 필요 | 별도 장비 불필요 | 분석 |
| Customization | 모델·프롬프트·생성 설정 전면 통제 | 제공자 지원 범위로 제한 | 분석 |
| Operations | 설치 후 최초 시도에 동작 | 3회 실패 후 성공 | 실측 |

Cloud 단가는 입력 $0.20 / 출력 $1.20 per 1M tokens (확인일 2026-09-15)이다.

### 7.3 Cloud API 호출 실패 이력

| 순번 | 오류 | 대응 |
|---|---|---|
| 1 | `gpt-4o-mini` 접근 권한 없음 (403) | 계정 사용 가능 모델 확인 후 변경 |
| 2 | `max_tokens` 미지원 (400) | `max_completion_tokens`로 교체 |
| 3 | `temperature=0` 미지원 (400) | 1로 변경 및 로컬 조건 재정렬 |

로컬 Ollama는 설치 후 최초 시도에 동작하였다. Cloud는 제공자가 정한 파라미터
규격을 준수해야 하며 규격 변경 시 코드 수정이 필요하다.

### 7.4 로컬 채택 근거

| 항목 | 판단 |
|---|---|
| 품질 | 격차가 경계 사례에 집중되며 정상 사례에서는 qwen3도 100% 달성 |
| 데이터 통제 | 검수 대상 광고는 위반 여부 미확정 상태이며 중개사 식별 정보를 포함. 대량 외부 전송 구조는 회피가 타당 |
| 비용 | 5회 호출에 약 1원으로 호출 요금 자체는 부담이 아님. 다만 로컬 운영에도 장비·전력·관리 비용이 발생하므로 총비용 0원으로 표기하지 않음 |

### 7.5 조건 불일치 항목

| 항목 | 내용 |
|---|---|
| 반복 수 | 로컬 2회 / Cloud 1회 (발제 지정) |
| 질문 수 | 로컬 10개 / Cloud 5개 (발제 지정) |
| context 길이 | 로컬은 `num_ctx` 4,096 명시, Cloud는 지정 불가 |
| 출력 한도 파라미터 | `num_predict` / `max_completion_tokens` |
| 실행 환경 | 로컬 GPU vs 원격 서버 + 네트워크 |
| 모델 규모 | 4B vs 미공개 |

1·2차 실험의 생성 설정 불일치는 3차에서 모두 해소하였다.

## 8. 선택 실습

### 8.1 양자화 비교 (q4_K_M vs q8_0)

동일 모델의 양자화 버전 2종을 동일 문항·동일 설정으로 비교하였다.
양자화 수준 외 모든 조건이 동일하다. (질문 10개 × 2회 × 2버전 = 40회, 성공 40/40)

| 지표 | q4_K_M | q8_0 | 차이 |
|---|---|---|---|
| VRAM | 3,030.9 MiB | 4,731.4 MiB | +1,700.5 (1.56배) |
| 생성 속도 | 88.82 tok/s | 69.57 tok/s | −22% |
| 품질 | **80.8%** | 75.9% | −4.9%p |
| 로딩 (워밍업) | 2.033초 | 4.719초 | 2.3배 |
| 다운로드 크기 | 2.5 GB | 5.0 GB | 2배 |

8비트가 압축률이 낮으므로 품질 우위가 예상되었으나 결과는 반대였다.

**측정 신뢰성** — q4_K_M이 기본 실험과 동일한 80.8%로 재현되었다. seed 42 적용으로
답변이 글자 단위로 일치하였다. seed 미지정 실험에서는 동일 모델이 75.6%와 82.5%로
분기하여 회차 편차가 양자화 간 차이를 상회하였다.

**q8 감점 원인** — 유형 칸 오기입이 대부분이다. Q04(사진 도용)와 Q07(미해당)에서
근거와 판정은 정확하였으나 유형을 '부존재·허위'로 오기입하였으며 2회차 모두 재현되었다.

**q8 우위 항목**

| 항목 | 내용 |
|---|---|
| Q03 숫자 생성 | 자료의 `400m`를 q8은 정확히 생성, q4는 2회차 모두 '40지점'으로 오생성 |
| Q06 토큰 생성 | q4 1회차에서 "4가 아닌 45도" 토큰 깨짐 발생, q8은 미발생 |
| Q10 범위 밖 안내 | q8만 손해배상·승소 가능성이 기준 밖임을 명시 |
| 간결성 | Q02에서 q4 234토큰 vs q8 124토큰, Q07에서 q4 186토큰 vs q8 104토큰 |

**정밀도로 해결되지 않는 항목** — 양 버전 모두 Q06, Q08에서 동일하게 실패하였다.

| 문항 | 실패 성격 |
|---|---|
| Q06 | 45도 < 90도 계산은 양측 정확. 첫 판정 줄에 '해당' 기입 후 후반부 정정 패턴 동일. 결론 확정 및 종료 능력의 문제 |
| Q08 | 수치 기준 부재 상황에서 양측 모두 단정. 판단 유보 필요 상황의 인식 실패 |

**결론** — 양자화 수준은 표기 정확도에 영향을 주나 판단 능력에는 영향을 주지 않았다.
본 Use Case에서는 q4_K_M이 합리적 선택이다. 다만 숫자 정확도가 중요한 태스크에서는
재검토 여지가 있다.

### 8.2 임베딩 실험

향후 RAG 도입 시 조항 자동 검색의 실현 가능성을 확인하였다.

- 스크립트: `embedding_test.py`
- 모델: `paraphrase-multilingual-MiniLM-L12-v2` (출력 384차원 고정)

**발제 예시 문장**

| 기준: "고양이가 소파 위에 있다." | 유사도 |
|---|---|
| 소파 위에 고양이가 앉아 있다. | **0.9509** |
| 오늘 주식시장이 상승했다. | −0.011 |

**프로젝트 자료 적용 — 사례 1** (방향, 정답 (다)) : 정답 1위, 2위와 차이 0.046

| 조항 | 유사도 |
|---|---|
| **(다) 방향 90도 이상 차이** | **0.6791** |
| (라) 직선거리 표시 | 0.6329 |
| (가) 옵션 성능 | 0.5896 |
| (나) 관리비 차이 | 0.4269 |

**프로젝트 자료 적용 — 사례 2** (직선거리, 정답 (라)) : **정답 2위**

| 조항 | 유사도 |
|---|---|
| (다) 방향 90도 이상 차이 | 0.3573 |
| **(라) 직선거리 표시** | 0.3298 |
| (나) 관리비 차이 | 0.2787 |
| (가) 옵션 성능 | 0.2143 |

사례는 "지하철역·도보 5분·13분", 조항은 "주요 교통시설·도보거리·직선거리"로
의미는 동일하나 어휘가 중복되지 않는다. 전체 점수대도 사례 1의 절반 수준이다.

**결론** — 단순 임베딩 유사도만으로는 법 조항 매칭을 신뢰할 수 없다. 2건 중 1건에서
오답 조항이 1위를 차지하였다. 검색이 오답 조항을 반환하면 생성 모델의 성능과 무관하게
판정이 실패한다. RAG 도입 시 모델 성능과 별개로 검색 단계의 정확도를 독립 평가해야 한다.

본 프로젝트가 in-context QA 방식을 채택한 것이 결과적으로 이 위험을 회피한 셈이다.

## 9. 한계 및 권고

### 9.1 확인된 한계

**모델 공통**

두 로컬 모델 모두 "제공 자료로는 판단할 수 없다"고 응답해야 할 상황을 인식하지
못하였다. 기준이 명확한 Q06에서는 판단을 유보하려 하고, 기준이 모호한 Q08에서는
단정하였다. 처리 방향이 반대이다.

**실험 설계**

| 항목 | 내용 |
|---|---|
| 평가셋 규모 | 질문 10개, 반복 2회. 문항 1개의 판정이 결과에 미치는 영향이 크다 |
| 측정 환경 | 노트북 1대 기준. 타 장비의 절대 속도와 합산하여 순위를 산출할 수 없다 |
| 재현성 | temperature 1에서는 seed 고정에도 회차 간 출력이 상이한 문항이 존재 |
| Cloud 조건 | 추론 미사용 상태로만 측정. Cloud의 100%도 추론 없이 얻은 결과 |
| Cloud 규모 | 파라미터 규모 미공개로 품질 차이를 모델 크기로 귀속할 수 없다 |
| 채점 | 개인 단독 수행. 체크리스트와 판정 규칙으로 주관을 축소하였으나 교차 확인은 미수행 |

### 9.2 운영 방식 권고

| 항목 | 권고 |
|---|---|
| 1차 선별 | 로컬 수행. 명확한 위반 유형은 qwen3로 충분하며 매물·중개사 정보가 외부로 전송되지 않는다 |
| 경계 사례 | 사람 검토로 이관. 판단 유보가 필요한 상황에서 모델이 결론을 강제하는 경향이 확인되었다 |
| 출력 검증 | 형식 검증 장치 필요. qwen3도 Q06에서 판정 블록을 복수 출력하였으므로 파싱 실패 및 판정 모순을 걸러내는 후처리가 요구된다 |
| 입력 차단 | 안내 범위를 벗어난 법적 판단 요청은 입력 단계에서 차단 |
| 모델 상향 | Cloud와의 격차가 경계 사례에 집중되므로 파라미터 상향 모델의 개선 여부 확인 필요. 단 조건이 일치하는 후보 확보를 위해 장비 확장이 선행되어야 한다 |

OPTIONS = {"temperature": 1, "num_predict": 1024, "num_ctx": 4096, "seed": 42}

| 항목 | 내용 |
|---|---|
| 프롬프트 | system 프롬프트 동일, 출력 형식 강제 (`판정:` / `유형:` / `근거:`) |
| 대화 이력 | 질문마다 messages 신규 생성. 이전 질문의 이력을 연결하지 않음 |

| 결측 처리 | 측정값 부재 시 `null`. 0으로 대체하지 않음 |
| 복수 판정 | 첫 번째 `판정:` 줄을 공식 출력으로 채점 |
