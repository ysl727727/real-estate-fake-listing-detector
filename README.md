# 허위매물 탐지 어시스턴트 — 로컬 LLM 모델 선정

매물 광고가 국토교통부고시 「부당한 중개대상물 표시·광고행위의 유형 및 기준」
(제2026-345호, 2026.7.3. 일부개정)에 해당하는지 판정하는 어시스턴트에 쓸
로컬 모델을 선정했습니다.

**최종 선정: `qwen3:4b-instruct-2507-q4_K_M`**

| | gemma3:4b | qwen3:4b-instruct-2507 | gpt-5.6-luna (Cloud) |
|---|---|---|---|
| 품질 (10문항) | 57.0% | **80.8%** | — |
| 품질 (공통 5문항) | 56.5% | 76.7% | 100% |

## 1. 무엇을 만든다고 가정했나

부동산 광고에는 실제와 다른 내용이 섞여 있습니다.
남향이라고 써놓고 실제는 북향이거나, 계약이 끝난 집을 계속 광고하면서
다른 매물을 권유하는 식입니다.

이런 광고를 자동으로 걸러주는 어시스턴트를 가정하고,
거기에 쓸 로컬 모델을 고르는 실험을 했습니다.

**판정 기준은 제가 만든 것이 아닙니다.** 국토교통부 고시에 정해져 있고,
"광고에 적은 방향과 실제가 90도 이상 차이 나면 위반" 같은 수치 기준이 들어 있습니다.

정답이 명확하게 정해지기 때문에 모델 비교를 공정하게 할 수 있다고 판단해
이 주제를 골랐습니다.

## 2. 기준을 먼저 정했습니다

### 2-1. 동일 조건에서 비교하기

이 과제의 목표는 로컬 LLM과 Cloud API 모델의 비교·선정입니다.
그래서 실험 전에 **맞출 수 있는 조건은 모두 맞추기로** 정했습니다.

| 항목 | 값 |
|---|---|
| system 프롬프트 | 10개 질문 전체, 모든 모델 동일 |
| temperature | 1 |
| seed | 42 |
| num_predict (출력 한도) | 1024 |
| num_ctx (전체 한도) | 4096 |
| 파라미터 규모 | 4B (로컬 두 모델 동일) |
| 양자화 수준 | Q4_K_M (로컬 두 모델 동일) |
| instruct 튜닝 | 두 모델 모두 instruct 버전 |
| 내부 추론 | 미사용 (로컬 non-thinking / Cloud reasoning_tokens 0) |

`instruct`는 지시를 따르도록 추가 학습된 버전

**조건을 맞추느라 전체 실험을 세 번 했습니다.**

Cloud 모델이 temperature 0을 지원하지 않고 기본값 1만 허용한다는 것을 모르고
시작했다가, 로컬을 1로 맞추고 전부 다시 돌렸습니다.
그 뒤 재현성을 높이기 위해 seed를 고정하고 한 번 더 돌렸습니다.

| 조건 | gemma3 | qwen3 | 격차 |
|---|---|---|---|
| temperature 0 / seed 42 | 55.1% | 85.0% | 29.9%p |
| temperature 1 / seed 미지정 | 50.1% | 75.6% | 25.5%p |
| **temperature 1 / seed 42 (본 집계)** | **57.0%** | **80.8%** | **23.8%p** |

세 조건 모두 선정 결과가 동일했습니다.

**Cloud의 내부 추론도 확인했습니다.** `gpt-5.6-luna`는 none부터 max까지 추론 수준을
조절할 수 있는 모델입니다. 실제로 추론이 동작하는지
`usage.completion_tokens_details.reasoning_tokens`로 측정한 결과,
단순 인사말과 실제 실험 문항(Q06) 모두 **0**이었습니다.
로컬 후보도 non-thinking 전용이라 이 항목까지 조건이 일치합니다.
(확인 스크립트: `check_reasoning.py`)

## 3. 질문은 이렇게 짰습니다

질문 10개를 고정했습니다.

- 명백한 사례 5개
- 애매한 사례(경계) 3개
- 자료에 없는 것을 묻는 질문 2개

### 실제 문항 예시 (Q06)

**① 판단 기준을 먼저 줍니다**

```
[판정 기준 발췌] 국토교통부고시 (제2026-345호, 2026.7.3. 일부개정)

중개대상물의 내용을 현저하게 과장한 광고(거짓·과장)의 유형과 기준
(가) 방향이 광고 시 제시한 방향과 90도 이상 차이가 나는 경우
(나) 주요 교통시설과의 거리를 실제 도보거리나 도보시간이 아니라
     직선거리로 표시·광고하는 경우
```

**② 광고 사례를 줍니다**

```
[점검 대상 광고]
· 광고 내용: F빌라 201호, 남향
· 확인된 사실: 실제 주된 채광 방향은 남동향(광고 표기와 45도 차이)

위 광고가 부당한 표시·광고에 해당하는지 판정하세요.
```

**③ 정해진 형식으로만 답하라고 지시합니다**

```
판정: 해당 / 미해당 / 판단불가 중 하나
유형: 부존재·허위 / 거짓·과장 / 기만적 / 해당없음 중 하나
근거: 적용한 조항과 판단 이유를 2~3문장으로
```

**정답**

```
판정: 미해당
유형: 해당없음
근거: 기준은 방향이 90도 이상 차이가 나는 경우인데,
남향과 남동향은 45도 차이라 기준에 미치지 못합니다.
```

상식적으로는 속인 것처럼 보이지만 **기준에 적힌 수치로는 위반이 아닙니다.**
모델이 자기 판단으로 답하는지, 주어진 기준을 적용하는지를 보는 문항입니다.

이런 함정을 두 개 넣었습니다. 다른 하나는 Q07로, 계약이 끝난 매물이 아직
게시 중인 사례입니다. 겉보기에는 위반 같지만 기준은 "기망 행위가 확인된 경우"를
요구하며 문의도 권유도 없었으므로 정답은 '미해당'입니다.


### 모델 간 순위를 매기는 기준

| 순위 | 기준 |
|---|---|
| 1 | 자료 밖 내용을 지어내지 않는가 |
| 2 | 답변 정확성 |
| 3 | 전체 응답 시간 |
| 4 | VRAM 사용량 |

속도와 메모리를 후순위로 둔 이유가 있습니다.
잘못 판정하면 멀쩡한 중개사가 제재를 받거나 진짜 허위매물이 그냥 넘어갑니다.
**빠르지만 틀린 답보다 느려도 맞는 답이 낫다**고 봤습니다.

## 5. 무엇이 결정적이었나

실험 전에 정한 우선순위를 적용한 결과 **qwen3를 선정**했습니다.
gemma3를 선택하지 않은 이유 중 두 가지가 결정적이었습니다.

### 5-1. 자료를 읽고도 반대로 답했습니다

Q07, 계약이 끝난 매물이 게시 중인 사례입니다. gemma3의 답변입니다.

> "통보받지 않았고, 문의도 없으며, 다른 매물을 권유한 사실도 **확인되었습니다.**
> 이는 계약이 체결된 사실을 알고 있음에도 실제 중개할 의사가 없는
> 허위·미끼 매물로 활용한 기망 행위에 해당합니다."

자료에는 "다른 매물을 권유한 사실도 **확인되지 않음**"이라고 돼 있습니다.
**부정을 긍정으로 뒤집어 읽고, 없는 사실을 근거로 위반을 인정했습니다.**
두 회차 모두 동일했습니다.

qwen3는 "기망 행위가 성립하지 않으므로 해당하지 않는다"고 정확히 판정했습니다.


### 5-2. 형식이 무너지고 지시를 지키지 않았습니다

Q05는 문제없는 정상 광고입니다. gemma3는 판정 칸에 '판단불가'를 기입했습니다.
자료에 면적·방향·거리가 모두 일치하고 계약 당일 삭제했다고 명시돼 있어
판단 가능한 사안입니다. 2회차는 "판단이 불가능합니다" 직후
"해당하지 않음을 확인할 수 있습니다"로 자기모순을 보였습니다.

앞선 실험에서는 판정 칸에 유형 선택지를 넣거나,
선택지 네 개를 통째로 복사해 출력한 적도 있습니다.

그리고 Q10에서 "중개 의무를 위반했다"고 판단했습니다.
자료의 판정 기준에는 의무 위반이라는 개념이 없습니다.
**법적 판단을 하지 말라고 지시문에 명시했는데도 자의적으로 판단했습니다.**

  qwen3는 928토큰을 쓰며 판정 블록을 네 번 출력하고도 첫 판정 줄을 틀렸습니다.
- **Q10**: 판정 자체를 '판단불가'로 처리하고 손해배상·승소 가능성이
  기준 범위 밖임을 명시했습니다. 로컬 두 모델은 승소 가능성을 언급조차 하지 않았습니다.

### 6-2. 주요 비교 기준

| 기준 | Local (qwen3) | Cloud (gpt-5.6-luna) | 구분 |
|---|---|---|---|
| Quality | 공통 5문항 76.7% (n=10) | 공통 5문항 100% (n=5) | 실측 |
| Latency | 평균 2.22초 (n=20) | 평균 2.73초 (n=5) | 실측 |
| Cost | 호출 요금 없음. 장비·전력·관리 비용 별도 | 5회 $0.001097 (입력 $0.20 / 출력 $1.20 per 1M) | 실측 |
| Security | 매물·중개사 정보가 외부로 나가지 않음 | 외부 API로 전송됨 | 분석 |
| Infrastructure | RTX 5060 8GB 노트북 필요 | 별도 장비 불필요 | 분석 |
| Customization | 모델·프롬프트·생성 설정 전부 통제 | 제공자 지원 범위로 제한 | 분석 |
| Operations | Ollama 설치 후 첫 시도에 동작 | 3회 실패 후 성공 (403 / max_tokens / temperature) | 실측 |

품질·응답 시간·비용은 실측, 데이터 통제·인프라·운영 부담은
서비스 요구사항에 따른 분석입니다.

### 6-3. 그럼에도 로컬을 선택한 이유

**성능 차이가 결정적이지 않았습니다.** qwen3와 Cloud의 격차는 경계 사례에 집중돼
있었고, 정상 사례에서는 qwen3도 100%였습니다.
실험 초반에 VRAM을 여유 있게 잡았으므로, 필요하면 조건에 맞는 상위 모델로
그 부분을 메울 수 있다고 판단했습니다.

**다루는 정보 때문입니다.** 검수 대상 광고는 아직 위반 여부가 확정되지 않은 상태이고,
그 광고를 올린 중개사가 누구인지도 함께 담깁니다.
이 조합이 대량으로 외부 서버를 거치는 구조는 피하는 것이 맞다고 봤습니다.

**비용은 고려 대상이 아니었습니다.** Cloud 5회 호출에 약 1원이 나왔습니다.
호출 요금 자체는 부담이 되지 않습니다.
다만 로컬 운영에도 장비·전력·관리 비용이 있으므로
호출 요금이 없다는 이유로 총비용을 0원으로 표기하지 않습니다.

### 6-4. 맞출 수 없었던 조건

- 반복 수(로컬 2회 / Cloud 1회)와 질문 수(10개 / 5개) — 발제 지정
- context 길이: 로컬은 `num_ctx` 4096 명시, Cloud는 지정 불가
- 출력 한도 파라미터명이 다름 (`num_predict` / `max_completion_tokens`)
- 실행 환경: 로컬 GPU vs 원격 서버 + 네트워크
- 모델 규모: 4B vs 미공개

## 7. 선택 실습

### 7-1. 양자화 비교 (q4_K_M vs q8_0)

같은 모델의 양자화 버전 2개를 같은 질문·같은 설정으로 비교했습니다.
기록: `results/runs_quant.jsonl`, `results/scores_quant.csv`

| 지표 | q4_K_M | q8_0 | 차이 |
|---|---|---|---|
| **VRAM** | 3,030.9 MiB | 4,731.4 MiB | +1,700.5 (1.56배) |
| **생성 속도** | 88.82 tok/s | 69.57 tok/s | −22% |
| **품질** | **80.8%** | **75.9%** | −4.9%p |
| 로딩 (워밍업) | 2.033초 | 4.719초 | 2.3배 |
| 다운로드 크기 | 2.5 GB | 5.0 GB | 2배 |

8비트가 덜 압축한 버전이니 품질이 더 좋을 것으로 예상했으나 **결과는 반대였습니다.**

**측정의 신뢰성**: q4_K_M이 기본 실험과 동일한 80.8%로 재현됐습니다.
seed 42 덕분에 답변이 글자 단위로 같았습니다.
seed를 지정하지 않았던 실험에서는 같은 모델이 75.6%와 82.5%로 갈렸고,
회차 편차가 양자화 간 차이보다 커서 해석이 불가능했습니다.

**q8의 감점 원인**: 대부분 유형 칸 오기입입니다.
Q04(사진 도용)와 Q07(미해당)에서 근거와 판정은 정확했으나
유형을 '부존재·허위'로 잘못 기입했고, 두 문항 모두 두 회차에서 재현됐습니다.

**q8이 앞선 항목도 있습니다.** Q03에서 자료의 `400m`를 q8은 정확히 생성했으나
q4는 두 회차 모두 '40지점'으로 잘못 생성했습니다.
Q10에서는 q8만 손해배상·승소 가능성이 기준 밖임을 명시했습니다.

**정밀도로 해결되지 않는 부분**: 두 버전 모두 Q06과 Q08에서 똑같이 실패했습니다.

- Q06: 45도 < 90도 계산은 둘 다 정확했으나, 첫 판정 줄에 '해당'을 쓰고
  뒤에서 정정하는 패턴이 같았습니다. **결론을 확정하고 멈추는 능력**의 문제입니다.
- Q08: '현저하게'의 수치 기준이 없는데 둘 다 단정했습니다.
  **판단 유보가 필요한 상황을 인식하지 못하는 문제**입니다.

정리하면 **양자화 수준은 표기 정확도에 영향을 주지만 판단 능력에는 영향을 주지
않았습니다.** 이 Use Case에서는 q4_K_M이 합리적인 선택입니다.

### 7-2. 임베딩 실험

지금은 질문마다 필요한 조항을 직접 골라 넣었습니다.
실제 서비스라면 자동으로 찾아와야 하므로, 그 검색이 가능한지 확인했습니다.

- 스크립트: `embedding_test.py`
- 모델: `paraphrase-multilingual-MiniLM-L12-v2` (384차원)

**발제 예시 문장에서는 잘 동작했습니다.**

| 기준: "고양이가 소파 위에 있다." | 유사도 |
|---|---|
| 소파 위에 고양이가 앉아 있다. | **0.9509** |
| 오늘 주식시장이 상승했다. | −0.011 |

**프로젝트 자료에서는 절반이 틀렸습니다.**

사례 1 (방향, 정답 (다)) — 정답이 1위였으나 2위와 차이가 0.046

| 조항 | 유사도 |
|---|---|
| **(다) 방향 90도 이상 차이** | **0.6791** |
| (라) 직선거리 표시 | 0.6329 |

사례 2 (직선거리, 정답 (라)) — **정답이 2위로 밀렸습니다**

| 조항 | 유사도 |
|---|---|
| (다) 방향 90도 이상 차이 | 0.3573 |
| **(라) 직선거리 표시** | 0.3298 |

사례는 "지하철역·도보 5분·13분", 조항은 "주요 교통시설·도보거리·직선거리"로
의미는 같으나 어휘가 겹치지 않습니다.

**단순 임베딩 유사도만으로는 법 조항 매칭을 신뢰할 수 없습니다.**
검색이 틀린 조항을 가져오면 모델이 아무리 좋아도 판정이 틀립니다.
향후 RAG를 도입한다면 모델 성능과 별개로
**검색 단계의 정확도를 따로 평가해야 합니다.**

## 8. 한계와 운영 권고

### 8-1. 확인된 한계

**선정한 모델도 완벽하지 않습니다.**
두 로컬 모델 모두 "이 자료로는 판단할 수 없다"고 말해야 할 상황을 인식하지 못했습니다.
기준이 명확한 Q06에서는 판단을 미루고, 기준이 모호한 Q08에서는 단정했습니다.
반대로 처리한 셈입니다.

- 질문 10개, 반복 2회의 소규모 평가셋입니다. 문항 하나의 판정이 결과를 흔들 수 있습니다.
- 노트북 1대에서 측정한 값이며, 다른 장비의 절대 속도와 합쳐 순위를 매길 수 없습니다.
- temperature 1에서는 seed를 고정해도 회차 간 출력이 달라지는 문항이 있었습니다.
- Cloud 모델은 추론 수준을 조절할 수 있으나, 이번 실험은 추론이 사용되지 않은 상태로만
  측정했습니다. **Cloud가 100%를 기록한 것도 추론 없이 얻은 결과입니다.**
- Cloud 모델의 파라미터 규모가 공개되지 않아 품질 차이를 모델 크기 차이로
  단정할 수 없습니다.
- 채점은 개인 수행자가 단독으로 했습니다. 체크리스트와 판정 규칙으로 주관을 줄였으나
  교차 확인은 하지 못했습니다.

자세한 관찰 사항은 `notes.md`에 정리했습니다.

### 8-2. 운영 방식 권고

- **1차 선별은 로컬** — 명확한 위반 유형은 qwen3로 충분합니다. 매물·중개사 정보가
  외부로 나가지 않습니다.
- **경계 사례는 사람 검토로 넘김** — 판단 유보가 필요한 상황에서 모델이 결론을
  강제로 내리는 경향이 확인됐습니다.
- **출력 형식 검증 장치 필요** — qwen3도 Q06에서 판정 블록을 여러 번 출력했습니다.
  파싱 실패나 판정 모순을 걸러내는 후처리가 있어야 합니다.
- **법적 판단 요청 차단** — 안내 범위를 벗어난 질문은 모델에 맡기지 말고
  입력 단계에서 걸러내는 편이 안전합니다.
- **모델 상향 검토** — Cloud와의 격차가 경계 사례에 집중됐으므로,
  파라미터를 키운 모델이 이 구간을 개선하는지 확인할 필요가 있습니다.
  다만 조건이 맞는 후보를 찾으려면 장비 확장이 필요합니다.

## D. 실험 조건 (전문)

```python
OPTIONS = {"temperature": 1, "num_predict": 1024, "num_ctx": 4096, "seed": 42}
```

- system 프롬프트 동일, 출력 형식 강제 (`판정:` / `유형:` / `근거:`)
- 질문마다 messages를 새로 생성 (이전 질문의 대화 이력을 잇지 않음)
- 판정 기준을 프롬프트에 직접 제공 (검색·RAG 없음)
- 모델당 워밍업 1회는 `is_warmup: true`로 표시하고 본 집계에서 제외
- 실패 회차는 `status: "error"`로 기록하며 삭제하거나 덮어쓰지 않음
- 측정값이 없으면 `null`로 두며 0으로 채우지 않음
- 답변에 판정이 여러 번 등장하면 첫 번째 `판정:` 줄을 공식 출력으로 채점
